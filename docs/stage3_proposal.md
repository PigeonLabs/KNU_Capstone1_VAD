# 3단계 제안: 위상 조건은 언제 도움이 되는가?

상태: **제안, 미실행**. 현재 예약된 메모리 제거 학습은 1단계 추가 검증입니다.

## 2단계에서 관찰한 사실

| 방법: AUROC (%) | R01 | R02* | R03 | R04 | 평균 |
|---|---:|---:|---:|---:|---:|
| 위상 조건부 최근접 prototype | 83.77 | 84.93 | 55.55 | 80.89 | 76.29 |
| 위상 무조건부 최근접 prototype | 86.24 | 85.57 | 62.34 | 79.33 | 78.37 |

위상 조건은 R04에서는 도움이 되었지만 나머지 세 장면에서는 무조건부보다 낮았습니다.
조건부가 본질적으로 나쁘다고 결론내릴 수는 없습니다. **위상 추정이 부정확한 것인지, hard routing이 너무 제한적인지,
현재 특징이 위상 구분에 적합하지 않은지**를 구분할 필요가 있습니다.

정상 holdout의 200-class 위상 top-1 정확도는 R01 11.48%, R02 21.09%, R03 9.08%, R04 7.56%였습니다.
200개 구간은 매우 세밀하고 실제 메모리는 20개 구간이므로, 이 수치만으로 사용 중인 위상 routing의 정확도가 낮다고
단정하지 않습니다. 먼저 20-bin 정확도·원형 오차를 확인합니다.

## 3A — 위상 추정 오차와 특징 구조 진단

- 이미 고정한 정상 영상 80/20 분할에서만 진단합니다. 검증 영상을 prototype/위상 모델 학습에 넣지 않습니다.
- 200-class 예측을 20-bin으로 합쳐 정확도, 원형 MAE, ±1 bin 정확도, 혼동행렬, confidence/오차 관계를 측정합니다.
- 위상별 prototype 점유 수, 동일 위상/다른 위상 특징 거리, 예측에 의해 실제 선택된 bin을 기록합니다.
- 정상 holdout에서 데이터의 주기 상대 위치를 주는 **참조 위상 routing**과 예측 위상 routing을 비교합니다.
  이는 정상 영상에서의 진단용 참조이며 이상 영상의 참 위상을 보장하는 oracle이 아닙니다.
- 테스트에서는 계속 예측 위상만 사용합니다. 테스트 길이·이상 라벨로 위상을 알려주지 않습니다.

## 3B — routing 방식만 바꾸는 비교

DINOv2 backbone, 특징 층, 데이터 분할, 공간별 prototype, 총 메모리 예산, 평가 프레임을 고정합니다.

| 비교 | 질문 |
|---|---|
| 무조건부 NN | 위상 정보 없이 얻는 기준 성능 |
| 현재 hard 1-bin NN | 2단계 조건부 기준선 |
| 원형 인접 ±1-bin NN | 작은 위상 오차를 허용하면 개선되는가? |
| posterior 상위 3-bin 후보 | 확률적으로 가능한 위상을 허용하면 개선되는가? |
| confidence 기반 무조건부 fallback | 불확실한 위상 판단을 강제하지 않으면 개선되는가? |

fallback 기준은 정상 검증셋의 위상 confidence/오차를 사용해 사전에 고정하고, 테스트 AUROC로 최적값을 선택하지 않습니다.
무조건부 메모리와 조건부 메모리는 같은 특징 표본과 같은 전체 prototype 수를 사용합니다.
재학습 없이 cache·메모리를 재사용할 수 있는 비교부터 시작합니다.

## 3C — 시간적 이상과 외형적 이상 점수의 역할 분리

- 외형 거리 점수, 위상 진행 오차, 둘의 결합을 분리해 기록합니다.
- 정상 R 영상의 holdout에서 정지·건너뛰기·역순 같은 통제 변형을 만들어 순서 이상에 반응하는지 점검합니다.
  원본 R 데이터는 보존하고, 파생 진단 데이터는 별도 manifest와 변형 구간을 기록합니다. S01–S12는 사용하지 않습니다.
- 통제 변형 실험은 작동 원리 확인용이며 실제 데이터셋의 이상 유형별 성능을 대체하지 않습니다.
- 외형/시간 이상 유형에 대한 실제 정답이 없으므로 자동 원인 분류 정확도를 주장하지 않습니다.

## 성공 판단

1. 참조 위상에서는 정상 매칭이 개선되는데 예측 위상에서만 악화된다면 위상 추정 개선을 우선합니다.
2. 인접/top-k/fallback routing에서 회복되면 위상 추정 불확실성을 허용하는 접근이 타당합니다.
3. 위상을 정확히 주거나 routing을 완화해도 이점이 없으면 위상 분할과 특징 표현 자체를 재검토합니다.
4. AUROC/AUPRC, 정상 오탐, 처리량, 메모리 사용량을 함께 기록합니다. 단일 장면 최댓값으로 결론내리지 않습니다.
5. 방법을 고정한 뒤 seed 0/1/2 및 영상 단위 bootstrap으로 변동을 확인합니다. 인접 프레임을 독립 표본으로 간주하지 않습니다.

먼저 복잡한 backbone 교체나 추가 loss를 넣기보다, **수행계획서의 핵심인 위상 조건이 실제로 기여하는지**를 확인하는 단계로 권합니다.
